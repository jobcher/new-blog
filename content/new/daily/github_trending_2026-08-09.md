分数：</b>无<br><br><b>影响范围：</b><br></p><blockquote>受影响组件：Linux kernel KVM/x86 legacy shadow page-walk length 4 和 5；<br>攻击者在 L1 中具备内核级执行能力；若作为宿主机本地提权使用，则需要能够访问 /dev/kvm。公开 PoC 在 /dev/kvm 为 0666 时可由低权限用户执行；</blockquote><br><b>注意:</b> 当前公开完整利用链依赖目标内核 kconfig、结构体布局、符号偏移和 VMM 内存后端。开启 CONFIG_LIST_HARDENED、CONFIG_DEBUG_LIST 等选项可阻断当前链表写利用，<b>但可能转化为宿主机拒绝服务，不等同于修复漏洞。</b><br><br><b>漏洞原理</b><br>KVM 处理 shadow MMU page fault 时会检查当前 root 是否失效，并在 shadow page 不足时调用 make_mmu_pages_available() 回收旧页。修复前，失效检查发生在回收之前；如果回收使 root 失效，后续 fetch 仍会在该 root 下创建映射。<br><blockquote expandable=""><b>1. 构造 pinned root 与 child 别名</b><br>攻击者使 shadow page X 同时作为嵌套页表 child 和 MMU root。顶层 reclaim 会跳过 root_count 不为 0 的 X，但递归 zap 未检查 child-&gt;root_count，仍可将 X 从 active list 删除并标记为 invalid。<br><br><b>2. 在 invalid root 下创建异常 child</b><br>page fault 已在回收前通过 stale-root 检查，回收后继续执行 fetch。新建 child C 继承 X 的 invalid 标记，却仍被加入 active_mmu_pages，破坏 invalid page 不得位于 active list 的约束。<br><br><b>3. 形成 use-after-free 与 post-free write</b><br>C 再次 prepare <a href="http://xn--,c-mv7d.link/" target="_blank" rel="noopener">时，C.link</a> 被加入 invalid list。commit zap 释放 C 后，active list 邻居仍指向 C.link；下一次 list_add() 会通过悬空节点向 C+8 写入新的内核指针。<br><br><b>4. cross-cache 与地址控制</b><br>公开 PoC 使用 518 MiB guest_memfd，shadow page quota 为 2652，通过固定 fault 和 3 个 PAE root 控制 MMU header slab 的释放顺序。Stage 1 [0x01000000, 0x04000000) 用于定位 C 和 active list，Stage 2 [0x04000000, 0x10000000) 用于获得页面 N。本次 C candidate 为 1，guest-side relocation 为 441，C=0x1627958，C page=0x1627000，N GPA=0x44a6000。<br><br><b>5. KASLR 泄露与宿主机代码执行</b><br>PoC 通过 Q1-Q8 八个写入阶段伪造 KVM MMU hash chain，将 pm_notifier 解释为 shadow page header，再通过 rcu_pm_notify_nb.10 泄露计算 KASLR slide。本次泄露地址为 0xffffffff83f54c40，slide 为 0x01000000。随后在 N page 中布置 wait entry 和 subprocess_info，通过 MONITOR、x2APIC LOWEST ICR、printk wake、SRCU 和 workqueue 进入 usermode helper，以 L0 内核凭据执行：<br>/bin/sh -c "umask 022; : &gt; /Zapscape"</blockquote><br><br><b>受影响对象：</b><br>向不受信任租户开放 nested virtualization 的 KVM/x86 云计算宿主机；<br>允许用户运行嵌套虚拟机的研发、测试、CI 和虚拟化平台；<br>/dev/kvm 对低权限用户可访问的多用户 Linux 主机。<br><br><b>处置建议：</b><br>优先升级到包含 2abd5287f083 或对应 stable backport 的内核，并重启宿主机加载新内核。<br>无法立即升级时，关闭不必要的 KVM nested virtualization，<b>停止向不受信任 L1 暴露嵌套虚拟化能力。</b><br>收紧 /dev/kvm 的 owner、group 和 mode，禁止无业务需要的低权限用户创建 KVM 虚拟机。<br>Intel 环境可临时避免同时向 L1 暴露 EPT PWL4/PWL5<br><br><b>参考链接:</b> <a href="https://github.com/V4bel/Zapscape" target="_blank" rel="noopener" onclick="return confirm('Open this link?\n\n'+this.href);">GitHub</a> / <a href="https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=2abd5287f083" target="_blank" rel="noopener" onclick="return confirm('Open this link?\n\n'+this.href);">Kernel</a><p></p>
